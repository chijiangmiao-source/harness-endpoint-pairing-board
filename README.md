# 线束针位连线核验板（harness-wiring-board）

纯前端核验工具：线束两端外壳方向相反时，装配员很容易把视觉上相邻的针位误认为同一根导线，
仅凭文字清单也难以发现交叉错接。本工具先录入两端针位与**严格一一对应**的预期关系，
再通过**鼠标拖拽**或**键盘选择**在 SVG 板上建立实际连线：

- 正确线显示**中性色**（深灰蓝）；
- 错接线**标红**，并在线旁与 A 端针位旁同时指出**预期对端**；
- 每个端点最多参与一条线，重复占用会在**相关端点旁**被拒绝，**原线保留**；
- 只有全部端点已连接且每条线都符合预期，整束状态才变为**通过**；
- 删除错线后两端立即恢复空闲，可直接补接，其余正确关系不会丢失。

无后端、无外部接口、无 mock：所有裁决都在浏览器本地完成。

---

## 一、录入约定（录入阶段）

1. **A、B 两端针位号分别录入**，每行一个针位号（空行与首尾空白自动忽略，顺序即画板上的排列顺序）。
2. 针位号在各自一侧必须**唯一**；重复针位会在该针位旁标出，不能进入连线阶段。
3. 为**每一个 A 端针位**从下拉框中指定唯一的预期 B 端针位。
4. 预期关系必须**覆盖两侧全部针位且严格一一对应**。以下任一情况都会在相关针位旁给出原因，并禁止进入连线阶段：
   - 某侧出现**重复针位**；
   - 某个 A 端针位**未指定**预期端；
   - 指定的预期端**不存在于 B 端清单**；
   - **多个 A 端针位指向同一个 B 端针位**；
   - 存在 B 端针位**未被任何 A 端针位指向**（覆盖不完整；两侧数量不一致时必然触发）。
5. 校验摘要显示「映射成立」后，「进入连线阶段」按钮才可用。进入后可随时返回修改录入
   （返回会清空当前连线，因为预期关系已变更）。

页面提供「填入示例数据（交叉关系）」按钮：A1→B3、A2→B1、A3→B4、A4→B2，可直接体验交叉核验。

## 二、连线操作约定（连线阶段）

- **鼠标 / 触屏**：在一侧针位上按下并拖拽到另一侧针位后松开；中途松手到空白处即取消。
- **键盘**：`Tab` 聚焦针位 → `Enter` 或 `空格` 选中第一端 → 聚焦另一端按 `Enter` 完成连线；
  再次按 `Enter` 可取消当前选择，`Esc` 取消选择，焦点位于已连接针位时按 `Delete`/`Backspace` 删除其连线。
- 每条线中部偏 A 端有 **× 按钮**（可聚焦、可键盘操作）用于删除该线。
- 选择了同一侧的两个针位、或任一端点已被占用时，操作会被拒绝，拒绝原因显示在**相关端点旁**，
  已存在的连线保持不变。
- 针位旁始终显示该 A 端针位的**预期对端**；错接线额外以红点与红标签标出实际对端与预期对端。

## 三、本地运行方法

环境要求：Node.js 18.20+、20.13+ 或 22+，npm 10+（开发环境实测 Node 20.20 / npm 10）。

```bash
npm install        # 安装依赖
npm run dev        # 开发模式，默认 http://localhost:5173

npm run build      # 类型检查（vue-tsc）+ 生产构建到 dist/
npm run preview    # 本地预览生产构建，默认 http://localhost:4173
```

### 测试

```bash
npm run test:unit  # Vitest：映射裁决、占用拒绝、整束状态与删线补接修复链路
npm run test:e2e   # Playwright：鼠标拖拽链路 + 键盘选择链路的端到端验收
```

`npm run test:e2e` 会自动执行构建、启动 `vite preview` 并在 Chromium 中跑 6 个验收用例
（首次运行需先 `npx playwright install chromium` 安装浏览器）。

## 四、Docker / Docker Compose

镜像同时包含页面静态服务（`vite preview`）与 Playwright 验收环境（Chromium 及其系统库）。

```bash
# 构建并启动页面（默认宿主端口 8080）：
docker compose up --build page
# 然后浏览器访问 http://localhost:8080

# 用 WEB_PORT 覆盖宿主端口（例如 9090）：
WEB_PORT=9090 docker compose up --build page
# 或复制 .env.example 为 .env 后修改 WEB_PORT
```

运行**一次性验收服务**（名为 `verify`，自动等待 page 健康，跑完 Playwright 后退出，退出码即验收结果）：

```bash
docker compose build
docker compose run --rm verify      # 6 个用例全部通过则退出码为 0
```

`verify` 通过 compose 内网访问 `http://page:4173`，不额外占用宿主端口；
页面容器仅把容器内 4173 映射到宿主 `${WEB_PORT:-8080}`。

## 五、目录结构

```
src/
  wiring/verification.ts        纯函数裁决层：映射校验 / 连线占用 / 单线裁决 / 整束状态
  wiring/verification.test.ts   Vitest 单元测试（23 个断言用例）
  components/MappingEntry.vue   录入阶段：针位清单、预期映射、针位旁拒绝原因
  components/WiringBoard.vue    连线阶段：SVG 画板、拖拽、键盘操作、红/中性裁决
tests/e2e/harness.spec.ts       Playwright 验收（录入拦截 + 鼠标链路 + 键盘链路）
Dockerfile / docker-compose.yml 多阶段构建；page 服务 + 一次性 verify 服务
```

## 六、裁决规则（与代码、测试一致）

| 场景 | 结果 |
| --- | --- |
| 针位重复 / 预期端缺失 / 多 A 指向同一 B / 覆盖不全 | 录入阶段拒绝进入，原因标注在相关针位旁 |
| 连接时任一端点已在线路上 | 拒绝新线，原因标注在被占用端点旁，原线保留 |
| 实际 B 端 = 预期 B 端 | 中性色线 |
| 实际 B 端 ≠ 预期 B 端 | 红色线 + 指出预期对端 |
| 端点未连齐 | 整束「未完成」 |
| 端点连齐但有错线 | 整束「全部已连接但存在 N 条错接」 |
| 端点连齐且全部正确 | 整束「通过」 |
| 删除错线 | 仅该线消失，其余线保留；补接正确后可重新通过 |
